# Метрики качества live-перевода EN -> RU

Цель: оценивать не только буквальную точность, но и пригодность результата как человеческих русских live-субтитров.

## Итоговая шкала

Итог: 100 баллов.

- Смысловая точность: 30.
- Человеческий русский: 25.
- Терминология и имена: 15.
- Работа с live-фрагментами: 15.
- Техническая пригодность для эфира: 15.

Acceptance gate для нормального эфира:

- итог >= 80/100;
- нет критических смысловых ошибок;
- нет систематического машинного русского;
- p90 latency <= 3500 ms;
- ключевые имена и продукты не искажаются;
- короткие фрагменты не достраиваются выдуманным смыслом.

## 1. Смысловая точность, 30

Проверяет, соответствует ли русский текст исходному EN.

Оценка:

- 5/5: смысл сохранен полностью.
- 4/5: мелкая неточность без потери сути.
- 3/5: общий смысл понятен, но есть искажения.
- 2/5: потеряна важная часть.
- 1/5: смысл сильно изменен.
- 0/5: не перевод или мусор.

Штрафовать отдельно:

- добавление фактов, которых нет в EN;
- смена субъекта или объекта;
- потеря отрицания;
- неверная причинно-следственная связь;
- перевод ASR-ошибки как факта, если ее можно было исправить по контексту.

## 2. Человеческий русский, 25

Главная метрика для ощущения "это сказал русский переводчик", а не модель.

Оценка:

- 5/5: естественно, кратко, звучит как русские субтитры.
- 4/5: немного книжно или машинно, но читается нормально.
- 3/5: понятно, но синтаксис тяжеловат.
- 2/5: русский текст неестественный, зритель спотыкается.
- 1/5: грамматика или сочетаемость заметно сломаны.
- 0/5: нерусский текст, артефакты, бессмыслица.

Проверять:

- нормальная русская сочетаемость;
- порядок слов без кальки с английского;
- краткость для двухстрочного overlay;
- отсутствие лишних вводных слов;
- отсутствие канцелярита там, где нужна живая речь;
- естественная пунктуация;
- нет финальной точки у незавершенного live-фрагмента, если она создает ложное завершение.

## 3. Терминология и имена, 15

Проверяет продуктовые имена, API, SDK, модели, компании и устойчивые термины.

Оценка:

- 5/5: все ключевые термины сохранены или переведены правильно.
- 4/5: мелкие стилистические расхождения.
- 3/5: часть терминов спорная.
- 2/5: важный термин искажен.
- 1/5: несколько терминов портят смысл.
- 0/5: терминология непригодна.

Правило:

- product names чаще keep unchanged: Gemini, Android, Firebase, Apple Intelligence, Project Astra.
- общие термины переводить естественно: developer tools -> инструменты для разработчиков.
- спорные термины решать через glossary только после повторяющейся ошибки.

## 4. Работа с live-фрагментами, 15

Проверяет, умеет ли система переводить неполные ASR-окна без выдумывания продолжения.

Оценка:

- 5/5: фрагменты склеиваются или переводятся осторожно.
- 4/5: редкие обрывы, но смысл не ломается.
- 3/5: заметны отдельные незавершенные куски.
- 2/5: часто переводятся хвосты без контекста.
- 1/5: поток выглядит как набор обрывков.
- 0/5: live-перевод невозможно читать.

Проверять:

- не отправляются слишком короткие хвосты;
- continuation-фрагменты присоединяются к предыдущей мысли;
- модель не завершает за спикера;
- соседние записи не дублируют одну и ту же мысль;
- ASR-ошибки исправляются только при явном контексте.

## 5. Техническая пригодность для эфира, 15

Оценка:

- 5/5: стабильно и быстро.
- 4/5: редкие задержки.
- 3/5: заметные паузы, но пользоваться можно.
- 2/5: регулярные задержки или пачки текста.
- 1/5: live-режим неудобен.
- 0/5: непригодно.

Ориентиры:

- median latency <= 2000 ms;
- p90 latency <= 3500 ms;
- max latency <= 6000 ms;
- timeout/error = 0 для нормального прогона;
- overlay не должен выдавать текст быстрее, чем его можно прочитать.

## Автоматические метрики

Без эталонного человеческого перевода:

- latency median/p90/max;
- доля error/timeout;
- доля cached;
- средняя длина EN/RU;
- suspicious duplicates;
- high-overlap соседние EN;
- короткие фрагменты до 5 слов;
- фрагменты с weak tail: to, of, and, that, with, new, more;
- артефакты письменности: CJK/Hebrew/Arabic, mojibake, лишние префиксы.

С эталонным человеческим переводом:

- COMET или COMETKiwi как модельная оценка, ближе к human judgement;
- chrF++ как устойчивый символьный baseline;
- BLEU только как вспомогательная метрика, не как главный критерий;
- MQM-разметка ошибок для ручной экспертной оценки.

## Ручной протокол

Для каждого кандидата брать 30-50 сегментов:

- начало, середина, конец;
- самые длинные;
- самые медленные;
- фразы с терминами;
- фразы после пауз;
- короткие live-хвосты.

Каждую пару EN/RU оценивать по пяти категориям выше. Ошибки классифицировать по причине:

- source/ASR;
- segmentation;
- model/prompt;
- glossary;
- latency/backend;
- overlay pacing.

## Вывод по двум последним записям

`translategemma:12b` дает хороший русский и нормальную скорость, но иногда делает перевод слишком редакторским: достраивает неполный live-фрагмент до законченной фразы и добавляет глаголы, которых нет в EN.

Главная правка нужна не в модели, а в prompt/segmentation:

1. Усилить правило для TranslateGemma: если source начинается с lowercase или выглядит как хвост, переводить как хвост без добавления субъекта и сказуемого.
2. Исправить mojibake в prompt/glossary.
3. В segmenter сильнее удерживать фрагменты, начинающиеся с `today from`, `from ... to ...`, `with ...`, `including ...`, пока не будет начало фразы или пауза.
4. Для live-overlay предпочитать краткие варианты: меньше `мы расскажем`, `покажем`, `существующих`, если этого нет в исходнике.

### Типовые ошибки TowerInstruct

1. Иногда уверенно переводит термин наоборот: `text to speech` -> `речь в текст`.
2. Хуже держит продуктовые имена и ASR-искажения: `Demis`, `Flash`, `LM arena`.
3. На длинных фрагментах добавляет смысл из контекста или прошлого окна. Пример: в slowest-записи появляется `библиотека всего, что вы хотите запомнить`, хотя в текущем EN этого нет.
4. Существенно медленнее: p90 4009 ms против 2376 ms у TranslateGemma.

### Где TowerInstruct лучше

Tower иногда дает более естественный русский на простых фразах:

- `И он может легко переключаться между языками.`
- `Это работает на более чем двадцати четырех языках.`

Это говорит, что Tower неплох как переводческая модель, но для текущего live-сценария его слабые места критичнее: скорость, терминология и устойчивость к грязным ASR-фрагментам.

### Рекомендуемые правки

1. Исправить mojibake в `ollama.py` и `glossary.yaml`.
2. Добавить glossary-правила:
   - `text to speech -> преобразование текста в речь`;
   - `speech to text -> преобразование речи в текст`;
   - `Demis -> Демис`;
   - `Flash -> Flash`;
   - `LMSYS Chatbot Arena leaderboard -> рейтинг LMSYS Chatbot Arena`.
3. Для TranslateGemma усилить prompt: lowercase/fragment input нельзя превращать в самостоятельную фразу с добавленным `мы расскажем`, `покажем`, `можно`.
4. Для Tower, если его тестировать дальше, использовать более жесткий prompt без system message и ближе к ChatML-стилю модели: короткая user-инструкция `Translate from English to Russian. Return only Russian.` плюс glossary.
